# 인증된 합성 consent 연결 시험

별도 opt-in APK의 메인 화면에서 `인증된 합성 동의 화면 열기`를 눌러 이동한다. 일반 debug 및 release 빌드에는 이 진입 버튼과 시험 Activity가 없다. 모의 서버와 앱 전용 localhost CA 구성은 [HTTPS mock 서버 실행](../tests/auth-consent-mock/README.md)을 따른다.

ROLE: APP · DOC-REV: 2.0.0 · RUBRIC: R03/R10. 이 화면은 테스트용 IdP·별도 합성 에이전트·테스트 서버에서만 동작하는 opt-in debug PoC다. 실제 브라우저, 사용자 인증, 운영 consent/grant/ACP, 위치 또는 기기 제어의 증거가 아니다. 기존 인증 없는 debug consent 화면과 별도이다.

`AuthenticatedConsentActivity`는 고정 합성 issuer/client와 명시적 합성 scope로 OIDC 세션을 얻고, 고정 HTTPS localhost 서버만 호출한다. CA는 opt-in APK의 localhost에만 한정되며 시스템·브라우저 신뢰를 바꾸지 않는다. access token은 메모리와 HTTPS Authorization 헤더에서만 사용하며 파일, Intent, receipt 또는 로그에 넣지 않는다. 서버는 합성 bearer의 issuer·audience·subject·scope 및 수명을 별도로 확인해야 한다. 이 검증은 아직 PC-MOBIUS-INTEGRATION의 운영 인증 계약이 아니다.

사용자는 `합성 세션 갱신`을 눌러 메모리 내 refresh token을 한 번 교환할 수 있다. 갱신 뒤 이전 상태와 검토 확인은 폐기하고 서버 상태를 다시 조회한다. access token이 기기의 단조 시계 기준으로 만료되면 화면의 기존 상태와 변경 버튼을 잠그지만 세션 갱신 또는 종료는 가능하다. refresh 실패 또는 결과 미확정이면 해당 세션을 폐기하고 재인증을 요구하며 자동 재시도하지 않는다. 이때 기존 합성 미확정 표시와 같은 프로세스에 남아 있는 보류 요청은 유지한다. 프로세스가 종료되면 보류 요청은 복구하지 못하고 boolean 표시만 남는다. 운영 토큰 보관·회수 정책이 아니다.

화면은 합성 목적·scope·TTL을 보여주고 체크 후에만 승인/회수를 전송한다. POST 전에 합성 미확정 **boolean 표시만** 앱 전용 저장소에 동기 기록한다. token, 개인 정보, 요청 본문, correlation 및 idempotency key는 저장하지 않는다. 실패하거나 응답·후속 조회가 불확실하면 새 변경을 잠그고, 같은 프로세스에 같은 요청이 남아 있을 때만 명시적 재전송을 허용한다. 프로세스 종료 후엔 표시만 복원되므로 이전 요청을 재전송하거나 결과를 복구했다고 주장하지 않는다. 사용자가 경고를 확인한 뒤 합성 표시만 삭제할 수 있으며, 이전 결과는 알 수 없다.

화면은 합성 요청 revision도 표시한다. 확인 체크는 조회한 서버 instance 및 grant 상태·revision·만료에 묶이고, 재조회나 세션 종료 시 삭제한다. 확인은 기기의 단조 시계로 60초가 지나면 해제된다. 이는 합성 UI의 검토 시한이며 서버 요청의 유효기간이 아니다. active grant의 기기 시계 기준 만료 시에도 확인을 해제한다. 최초 전송 직전 고정 합성 요청과 grant를 다시 조회해 다르거나 검토 시한이 지났으면 POST를 시작하지 않는다. 이때에도 이미 기록한 미확정 표시를 보수적으로 유지하므로 사용자는 표시만 삭제하고 현재 상태를 다시 조회할 수 있다. POST를 시작한 뒤 응답이 유실되면 같은 프로세스에서 기존 key·본문 재전송을 허용한다. 기기 시계의 정확성은 보장하지 않으며, 사전 조회와 전송은 원자적이지 않다. 서버가 실제 권한·회수·만료를 판정해야 한다.

화면이 전경일 때 active grant가 표시된 만료 시각에 기기 시계가 도달하면 기존 상태를 미확인으로 바꾸고 새 승인·회수를 잠근다. 화면 복귀 시에도 확인한다. 이는 기기 시간에 따른 재조회 안내일 뿐 실제 만료 판정이나 권한 회수가 아니며, 다시 로그인해야 할 수 있다. 서버 상태를 재조회한 뒤에만 새로운 상태를 표시한다.

Activity 종료 중 전송 직전의 종료·중단 여부와 세션을 다시 검사하지만, 그 검사 직후 종료되거나 이미 전송된 HTTP 요청이 서버에서 처리되는 것을 취소한다고 보장하지 않는다. 이 경우에도 미확정 표시를 남긴다. 성공 receipt는 서버 instance와 correlation을 확인하고 서버의 현재 상태를 다시 읽어야 표시를 해제한다. 테스트 서버의 휘발성 ledger나 instance ID는 운영 권한 또는 실제 복구 보장이 아니다.

응답이 조금씩 계속 도착하더라도 요청 시작 후 10초 경과 여부를 헤더와 각 본문 read 전후에 검사한다. 연결·헤더 처리 중이나 이미 진행 중인 read는 차단된 호출이 돌아온 뒤에야 경과 여부를 검사하므로 정확한 전체 시간 제한은 아니다. 연결과 read에는 각각 기존 5초 소켓 제한을 적용하지만, 차단된 요청 본문 쓰기의 전체 시간 제한은 보장하지 않는다. 시간 초과를 포함한 변경 요청 실패는 서버 처리 여부를 단정하지 않고 미확정 상태로 남긴다. 응답 기한 단위시험은 `app/tests/auth-consent-mock/test-response-deadline.sh`로 실행한다.

정상·부정·종료/재시작·토큰 만료와 기기 정리 증거는 별도 receipt로 기록한다. 실제 연동 전에는 issuer, client, verified App Links, API의 principal·scope·idempotency·durability 계약, secret 보관 및 운영 테스트가 필요하다.
