# Application security boundary

Scope: Android product launcher, external-browser OIDC, encrypted sessions, HTTPS location transport, location parsing/rendering, and `pc-mobius/mobile-api`. This is a source/attack-boundary review and reproducible test scope, not an independent penetration-test certification.

| Asset / entry point | Attacker control | Required boundary |
| --- | --- | --- |
| Authorization callback exported for provisioned builds | Another app can invoke/intercept the custom scheme | Exact redirect, transaction state and issuer; PKCE S256; verified ID-token signature, nonce and audience; one exchange |
| Discovery, JWKS and token responses | Network input from the provisioned issuer | Platform TLS trust and hostname validation, TLS 1.3, redirects disabled, bounded strict UTF-8 JSON, duplicate/depth rejection, restricted signing algorithm and keys |
| Saved authentication | Late worker completion, process death, altered ciphertext | Android Keystore AES-GCM, origin/issuer/client context, durable refresh consumption, epoch-checked saves, cancellation/logout cannot restore credentials |
| App update / service configuration | Persisted configuration from an older release | Current release API origin must control effective destination and invalidate old-origin encrypted sessions |
| Mobile API bearer | Arbitrary header/JWT bytes and replay of a stolen bearer | Trusted configured keys only; signature, issuer, audience, expiry and location scope; strict JSON/base64url; no caller-supplied principal |
| Location authorization | Authenticated user requests another principal's device | Administrator-owned subject/UE binding; when a grant is referenced, active matching grant/consent/subject/revision/scope; denied output has no coordinates or observation timestamps |
| Event/state input | Malformed, oversized, stale, future and out-of-order records | Bounded state and response sizes; finite coordinates and accuracy; calendar/freshness validation; latest invalid observations cannot reveal an older fix as current |
| HTTP listener | Concurrent/slow requests, duplicate auth headers, oversized input | Loopback binding, bounded headers/concurrency/sockets/time, no arbitrary methods/bodies, generic errors; production reverse-proxy rate limits |
| Map SDK and public tiles | Provider content and viewport inference | No auth token sent as map credentials; authorized finite coordinates only; reset removed locations/camera; preserve attribution and disclose provider viewport knowledge |

High-value fuzz invariants are rejection without a crash, bounded work, no credential logging, no principal change, and no coordinates in denied/unavailable results. Inputs include malformed UTF-8 and surrogate escapes; repeated decoded JSON keys; excessive nesting; number overflows; noncanonical base64url; invalid algorithms/key directives; duplicate URI parameters and encoded callback paths; prototype-shaped record names; malformed grant/consent IDs/revisions; out-of-order/future/undated events; and transport header/path injection.

The review found and closed a release-profile migration concern: persisted `api_base` could override a newer build-pinned origin while the same issuer/client kept old-origin credentials usable. `MobileSessionStore.getApiBaseUrl()` now uses `ServiceOrigin.effective()`, which selects the current provisioned origin for release reads; old-origin encrypted sessions then fail their origin-context comparison. Three `ServiceOriginTest` cases pass, including migration selection, safe-origin normalization and 1,024 out-of-range ports. This is boundary-level regression evidence, not a physical-device upgrade-flow claim. A repeated per-binding event scan was also measured at approximately 371 ms for an allowed 20,000-event/100-binding fixture; the single per-request UE index reduced warm runs to approximately 8 ms while preserving selection semantics.

The existing Nimbus 9.47 dependency matched CVE-2025-53864/GHSA-xwmg-2g98-w7v9 for nested-JSON denial of service. The application pre-parser limits nesting, and the release dependency was updated to 10.10; package-version SCA evidence records the final result separately. The advisory identifies 10.0.2 as the fix for the affected newer branch. [OSV advisory](https://osv.dev/vulnerability/GHSA-xwmg-2g98-w7v9), [upstream issue](https://bitbucket.org/connect2id/nimbus-jose-jwt/issues/583/stackoverflowerror-due-to-deeply-nested)

Residual deployment boundaries: the custom redirect scheme has no OS-verified domain ownership; actual IdP refresh rotation/reuse detection/revocation and complete login require operator testing; the upstream portable mutation runner must remain private behind authenticated ingress; public map services learn tile viewports and provide their own availability guarantees. Offline revocation cannot remove a location already observed by an authorized user. Rooted/compromised OS or process memory is outside Android Keystore's application-level boundary. No system or browser CA trust changes are required by this verification.
