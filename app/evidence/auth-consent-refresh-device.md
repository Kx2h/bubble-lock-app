# 합성 인증 동의 세션 갱신 공기계 시험

ROLE: APP · DOC-REV: 2.0.0 · RUBRIC: R03/R10. 2026-10-28 Android 14 공기계에서 opt-in debug APK SHA-256 `e35af5cb680d62d1cf9af5fd17023f78e2908a85b10e88a4ea7e773e0608eeaa` 및 별도 합성 에이전트를 사용했다. 합성 IdP·동의 서버와 앱 한정 테스트 CA만 사용했으며 실제 브라우저, 사용자, 권한 또는 운영 인증을 시험하지 않았다.

합성 인증 직후 사용자가 세션 갱신을 선택해 성공했고 화면은 서버 상태 재조회가 필요하다고 표시했다 ([화면](auth-consent-refresh-success.png)). 상태를 조회하고 합성 승인을 보낸 뒤 서버가 응답을 유실하도록 하여 결과 미확정 상태를 만들었다. IdP를 중단한 뒤 세션 갱신은 실패했고 기존 세션이 폐기되면서 재인증과 이전 요청 미확정 상태를 표시했다. 승인·회수는 잠겼다 ([화면](auth-consent-refresh-failed-pending.png)).

IdP를 다시 시작하고 같은 프로세스의 앱에서 합성 재인증한 뒤, 사용자가 기존 미확정 요청 재전송을 명시적으로 선택하자 동의 서버의 동일 인스턴스에서 보관된 기존 요청이 정산되어 서버의 `active` 상태가 표시됐다 ([인증 직후](auth-consent-refresh-reauth-pending.png), [재조회](auth-consent-refresh-recovered.png)). 이 합성 결과는 운영 권한이나 실사용자의 인증을 증명하지 않는다. 프로세스 종료 후에는 boolean 표시만 남으므로 이전 요청을 재전송할 수 없다.

토큰 만료 후 화면 전환은 이 기기 시험에서 기다려 재현하지 않았으며, 기존 단위시험은 만료된 access token 이후 refresh를 허용하는 세션 로직을 확인한다. 중단 전송의 네트워크 수준 재시도 부재나 모든 장애 상황의 정산은 이 시험으로 보장하지 않는다.

직접 시작한 서버, 테스트 에이전트, `18443`·`18788` reverse 및 UI dump를 제거했다. 이전 앱을 데이터 삭제 없이 복원하여 설치 APK SHA-256 `bb9dc64aebefbc89c9812b7954181d88e00432ee844e5b8610ba50b463d5ee24`를 확인했다. 기존 `8787` reverse와 임시 CSE는 유지했고 시스템·브라우저 인증서 신뢰는 변경하지 않았다. 토큰과 서버 비밀은 기록하지 않았다.
